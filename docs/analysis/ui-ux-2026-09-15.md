## 2. Point 1: Cell Value Viewer

### 2.1 Diagnosis of the Current Implementation
- **Location**: [frontend/src/components/CellValueViewer.tsx](file:///home/matheusdutra/Projects/wisp/frontend/src/components/CellValueViewer.tsx) and [frontend/src/components/ResultGrid.tsx#L689-L695](file:///home/matheusdutra/Projects/wisp/frontend/src/components/ResultGrid.tsx#L689-L695).
- **UX problem**: The current component mounts a centered floating modal with a dark backdrop (`.grid-edit-overlay`, [App.css#L1486-L1494](file:///home/matheusdutra/Projects/wisp/frontend/src/App.css#L1486-L1494)). It blocks the view of the rest of the table, requires closing the modal to inspect another row/column, and breaks the fast record-navigation flow for rows containing long JSON/XML.

### 2.2 UI Architecture Recommendations
- **Position (Right vs. Left)**:
  - **Recommendation**: **Right of the grid**.
  - **Rationale**: The left already holds the main catalog navigation tree (`Sidebar`). Placing an inspector left of the grid would make two vertical columns compete for the same visual quadrant. The industry pattern (DBeaver "Value / Panels", DataGrip, Chrome DevTools) uses the right side or the footer; the right preserves natural LTR reading (leading columns/PKs on the left, detailed inspection on the right).
- **Resizing with `useDragResize`**:
  - Reuse the project's already-tested [useDragResize.ts](file:///home/matheusdutra/Projects/wisp/frontend/src/lib/useDragResize.ts) hook directly, configured with `axis: 'x'`, `initial: 320`, `min: 240`, `max: 600`, and `storageKey: 'wisp:cellValueViewerWidth'`.
  - Insert a `<div className="resize-handle resize-handle-v" ... />` between the `DataEditor` container and the inspector panel.
- **Sync with Active Selection**:
  - `ResultGrid` already manages `gridSelection` ([ResultGrid.tsx#L125](file:///home/matheusdutra/Projects/wisp/frontend/src/components/ResultGrid.tsx#L125)).
  - When the panel is open/active (`isViewerOpen === true`), a `useEffect` listening to `gridSelection?.current?.cell` (or derived from the active row and column) automatically updates the inspector's `rawValue` and `columnName`.
  - **Opening affordance**:
    1. Keep the "View value…" context-menu item ([ResultGrid.tsx#L628-L635](file:///home/matheusdutra/Projects/wisp/frontend/src/components/ResultGrid.tsx#L628-L635)) to open/focus the panel.
    2. Add a quick toggle button to the grid toolbar ([ResultGrid.tsx#L546-L567](file:///home/matheusdutra/Projects/wisp/frontend/src/components/ResultGrid.tsx#L546-L567)) or a mini-tab collapsed on the right side (with a `{ }` or `< >` icon) to open/close the side panel.
- **Feature Preservation**:
  - Keep the format selector ([valueFormat.ts](file:///home/matheusdutra/Projects/wisp/frontend/src/lib/valueFormat.ts)), line-wrap toggle (`wrap`), copy button, and the panel's internal header layout fully intact.

## 3. Point 2: Minimizable / Collapsible Sidebar

### 3.1 Diagnosis of the Current Implementation
- **Location**: [frontend/src/components/Sidebar.tsx](file:///home/matheusdutra/Projects/wisp/frontend/src/components/Sidebar.tsx) and its consumer in [frontend/src/components/ConsoleTab.tsx#L756-L764](file:///home/matheusdutra/Projects/wisp/frontend/src/components/ConsoleTab.tsx#L756-L764).
- **UX problem**: The sidebar can be drag-resized down to the 180px minimum but cannot be collapsed. On smaller screens or when reviewing wide tables with many grid columns, the sidebar takes up unneeded horizontal space.

### 3.2 Collapse Strategy (Hidden vs. Icons)
- **Icons-Only Assessment**: The Wisp sidebar holds a text search (`input`) and a dynamic schema/table tree ([Sidebar.tsx#L175-L250](file:///home/matheusdutra/Projects/wisp/frontend/src/components/Sidebar.tsx#L175-L250)). An icons-only sidebar of databases without labels adds no real value (there is no global-shortcut toolbar there).
- **Recommendation**: **Full Collapse to 0px with Expand Button**.
  - In the collapsed state: the sidebar goes to `width: 0` (with `display: none` or `overflow: hidden; border: none`), freeing 100% of the width for the editor and grid.
  - A subtle button stays available in the top-left of the secondary bar ([ConsoleTab.tsx#L710](file:///home/matheusdutra/Projects/wisp/frontend/src/components/ConsoleTab.tsx#L710)) or as a narrow tab on the left edge: a side-panel icon (e.g. `Sidebar Toggle` `[| ]`), with tooltip "Expand schemas panel (Ctrl+B)".
  - In the expanded sidebar header ([Sidebar.tsx#L165-L173](file:///home/matheusdutra/Projects/wisp/frontend/src/components/Sidebar.tsx#L165-L173)), next to the "Schemas & Tables" title or the "Refresh" button, place the collapse button (`«` or a left-chevron icon).
- **Persistence**:
  - Save a boolean key `wisp:sidebarCollapsed` (`true` | `false`) in `localStorage`.
  - On expanding again, restore the previous width saved by `useDragResize` (`wisp:sidebarWidth`).
