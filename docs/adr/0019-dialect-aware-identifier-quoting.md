# ADR 0019 — Dialect-Aware Identifier Quoting & Session Metadata

**Status:** Accepted  
**Date:** 2026-09-22  

## Context

Different SQL dialects use different character quoting rules for identifiers (tables, schemas, columns):
- **PostgreSQL**: Standard double quotes (`"my_table"`).
- **SQLite**: Double quotes (`"my_table"`), backticks, or brackets.
- **MySQL / MariaDB**: Backticks (`` `my_table` ``). Double quotes (`"my_table"`) are interpreted as string literals unless the server is configured with the `ANSI_QUOTES` SQL mode.

Currently in the frontend:
- `TableTab.tsx`: Hardcodes `const qualified = schema === 'main' ? `"${table}"` : `"${schema}"."${table}"`;`.
- `foreignKeyNav.ts`: Hardcodes `"${column}" = ...` and `"${schema}"."${table}"`.
- `gridEditPreview.ts`: Hardcodes `"${pk}" = ...` and `"${column}" = ...`.

When connected to a standard MySQL or MariaDB instance (which defaults to without `ANSI_QUOTES`), queries generated by `TableTab` fail with syntax errors because double quotes are parsed as string literals instead of table/column identifiers.

Furthermore, the frontend does not consistently know the dialect or database engine of a given tab.

## Decision

Expose the session's dialect in backend responses and create a centralized, tested frontend quoting library.

### 1. Backend Session Metadata

Update `Connect` and `ConnectSaved` in `app.go` and `internal/session/manager.go` to return session metadata:

```go
type SessionMetadata struct {
    TabID         string `json:"tabId"`
    Driver        string `json:"driver"`        // "postgres", "sqlite", "mysql", "mariadb"
    Dialect       string `json:"dialect"`       // "postgres", "sqlite", "mysql"
    ServerVersion string `json:"serverVersion"` // e.g. "PostgreSQL 16.1", "MySQL 8.4.0", "SQLite 3.45.1"
}
```

- When connecting, query dialect/version (e.g. `SELECT version()` for Postgres/MySQL, `SELECT sqlite_version()` for SQLite).
- Cache metadata in the session object in `internal/session/manager.go`.

### 2. Centralized Frontend Dialect Helper (`frontend/src/lib/sqlDialect.ts`)

Create `frontend/src/lib/sqlDialect.ts` with comprehensive unit tests:

```typescript
export type Dialect = 'postgres' | 'mysql' | 'sqlite';

export function normalizeDialect(driver: string): Dialect {
    if (driver === 'mysql' || driver === 'mariadb') return 'mysql';
    if (driver === 'sqlite') return 'sqlite';
    return 'postgres';
}

export function quoteIdent(identifier: string, dialect: Dialect): string {
    if (dialect === 'mysql') {
        return '`' + identifier.replace(/`/g, '``') + '`';
    }
    return '"' + identifier.replace(/"/g, '""') + '"';
}

export function qualifyTable(schema: string | undefined, table: string, dialect: Dialect): string {
    const quotedTable = quoteIdent(table, dialect);
    if (!schema || schema === 'main' || (dialect === 'mysql' && schema === 'def')) {
        return quotedTable;
    }
    const quotedSchema = quoteIdent(schema, dialect);
    return `${quotedSchema}.${quotedTable}`;
}
```

### 3. Replace Hardcoded Quotes

Refactor:
1. `TableTab.tsx`: Retrieve `dialect` from session or props and call `qualifyTable(schema, table, dialect)` and `quoteIdent(col, dialect)`.
2. `foreignKeyNav.ts`: Accept `dialect: Dialect` parameter in `buildForeignKeyFilterQuery`.
3. `gridEditPreview.ts`: Accept `dialect: Dialect` in `buildUpdatePreview`, `buildDeletePreview`, and `buildInsertPreview`.

## Consequences

- **Pros**:
  - Full compatibility with MySQL and MariaDB databases without requiring `ANSI_QUOTES` configuration.
  - Eliminates SQL injection vulnerabilities from unescaped table or column names containing quotes.
  - Centralizes identifier quoting rules in a single, thoroughly tested module.
- **Cons**:
  - Tab state must track `dialect`.

## Acceptance Criteria

1. Running `TableTab` on a MySQL database without `ANSI_QUOTES` generates backtick-quoted queries (`` `table` ``) and loads data without error.
2. Identifiers containing embedded quotes (e.g. `table"name` on Postgres, `table`name` on MySQL) are correctly escaped with doubled quotes.
3. Unit tests in `sqlDialect.test.ts` verify identifier escaping for all 3 dialects.
